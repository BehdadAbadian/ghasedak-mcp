# قاصدک MCP

سرور محلی MCP برای ارسال پیامک و استعلام حساب از طریق [وب‌سرویس قاصدک](https://ghasedak.me/docs). دستیار برنامه را روی کامپیوتر کاربر با `stdio` اجرا می‌کند و برنامه با کلید همان حساب از طریق HTTPS به قاصدک وصل می‌شود.

## پیش‌نیازها

- Node.js نسخهٔ ۲۲ یا بالاتر، npm و یک دستیار سازگار با MCP محلی
- کلید API پنل قاصدک
- برای ارسال عادی، خط مجاز حساب. برای OTP، قالب فعال و نام پارامترهای آن

## تنظیم کلید API

`GHASEDAK_API_KEY` تنها متغیر الزامی است. کلید وب‌سرویس را از پنل قاصدک بگیرید. برنامه آن را در هدر `ApiKey` به وب‌سرویس قاصدک می‌فرستد. در نصب از npm آن را در تنظیمات شخصی دستیار بگذارید. در اجرای مستقیم با Node می‌توانید کلید را در یک فایل محلی خارج از مخزن نگه دارید و با `--env-file` به برنامه بدهید. پس از تعویض کلید، اتصال MCP را دوباره راه‌اندازی کنید.

## قبل از نصب

ارسال پیامک و OTP واقعی است و از اعتبار حساب هزینه کم می‌کند. تأیید ارسال در دستیار انجام می‌شود. تأیید ابزارهای ارسال را در دستیار فعال کنید و قبل از تأیید، گیرنده‌ها، خط فرستنده در صورت کاربرد و متن پیام یا قالب را بررسی کنید. کلید API را در تنظیمات محلی نگه دارید و آن را در گفتگو یا Git وارد نکنید.

## نصب از npm

نمونه‌های زیر برای نصب نسخهٔ مشخص بسته از npm هستند. برای اجرای نسخهٔ محلی مخزن، بخش [اجرا از سورس](#اجرا-از-سورس) را ببینید.

### Codex دسکتاپ یا CLI

بلوک زیر را به `~/.codex/config.toml` اضافه کنید. اگر بخش `mcp_servers.ghasedak` از قبل وجود دارد، همان را ویرایش کنید. مقدار نمونه را با کلید API خودتان جایگزین کنید.

```toml
[mcp_servers.ghasedak]
command = "npx"
args = ["-y", "ghasedak-mcp@0.1.0"]
default_tools_approval_mode = "prompt"

[mcp_servers.ghasedak.env]
GHASEDAK_API_KEY = "<YOUR_GHASEDAK_API_KEY>"
```

اگر Codex در ویندوز نتوانست `npx` را اجرا کند، مقدار `command` را به `"cmd"` و `args` را به `["/c", "npx", "-y", "ghasedak-mcp@0.1.0"]` تغییر دهید.

### سایر دستیارها

اگر فایل تنظیمات از قبل سرورهای دیگری دارد، فقط ورودی `ghasedak` را به بخش موجود اضافه کنید.

```json
{
  "mcpServers": {
    "ghasedak": {
      "command": "npx",
      "args": ["-y", "ghasedak-mcp@0.1.0"],
      "env": {
        "GHASEDAK_API_KEY": "<YOUR_GHASEDAK_API_KEY>"
      }
    }
  }
}
```

اگر دستیار در ویندوز `npx` را اجرا نکرد، `command` را روی `cmd` و `args` را روی `["/c", "npx", "-y", "ghasedak-mcp@0.1.0"]` بگذارید.

- **Claude Desktop** — در ویندوز فایل `%APPDATA%\Claude\claude_desktop_config.json` را ویرایش و برنامه را دوباره راه‌اندازی کنید.
- **Cursor** — ورودی را به بخش `mcpServers` در فایل شخصی `~/.cursor/mcp.json` اضافه کنید. [راهنمای Cursor](https://cursor.com/docs/mcp)
- **VS Code در حالت محلی** — ورودی را در `.vscode/mcp.json` زیر `servers` بگذارید و `"type": "stdio"` را مشخص کنید. در `env` مقدار `GHASEDAK_API_KEY` را `${input:ghasedak-api-key}` بگذارید. در آرایهٔ `inputs` در سطح ریشه، ورودی زیر را اضافه کنید تا VS Code کلید را جداگانه بپرسد. [مرجع تنظیمات MCP در VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration#_input-variables-for-sensitive-data)

```json
{"id":"ghasedak-api-key","type":"promptString","description":"Ghasedak API key","password":true}
```

## اجرا از سورس

در ریشهٔ مخزن `npm ci` را اجرا کنید. در نمونهٔ بالا، `command` را به `node` تغییر دهید و در `args` فقط مسیر کامل `src/index.js` را بگذارید.

برای **Codex دسکتاپ یا CLI**، فایل محلی `ghasedak.env` را خارج از مخزن بسازید و در آن `GHASEDAK_API_KEY=YOUR_GHASEDAK_API_KEY` را با کلید خودتان پر کنید. بلوک زیر را در `~/.codex/config.toml` بگذارید و مسیرهای نمونه را با مسیرهای کامل سیستم خودتان جایگزین کنید.

```toml
[mcp_servers.ghasedak]
command = "node"
args = [
  "--env-file=C:/path/to/ghasedak.env",
  "C:/path/to/ghasedak-mcp/src/index.js"
]
default_tools_approval_mode = "prompt"
```

اگر دستیار `node` را پیدا نکرد، مسیر کامل فایل اجرایی Node.js را در `command` بگذارید.

## اولین تست بعد از نصب

بعد از ذخیرهٔ تنظیمات، دستیار را دوباره راه‌اندازی کنید. در Codex با `/mcp` بررسی کنید که سرور `ghasedak` دیده می‌شود. [راهنمای MCP در Codex](https://learn.chatgpt.com/docs/extend/mcp#connect-codex-to-an-mcp-server)

از دستیار بپرسید «ماندهٔ اعتبار حساب قاصدک من چقدر است؟» اگر ابزار `get_balance` مقدار `data.credit` را برگرداند، اتصال MCP و دسترسی کلید به API تأیید شده است. این استعلام پیامکی ارسال نمی‌کند.

## ابزارها

- `get_balance` بدون ورودی. مقدار `data.credit` همان موجودی کیف پول گزارش‌شده از API است.
- `get_delivery_status` حداکثر ۱۰۰ شناسهٔ رشته‌ای در `ids` می‌گیرد. `idType` پیش‌فرض `messageId` است و برای شناسهٔ مرجع می‌توان `clientReferenceId` داد. در `data` هر ردیف، کد `status` و معنی آن در `statusLabel` را دارد. اگر قاصدک شناسه‌ای را پیدا نکند، ردیف آن با `status: null` و `statusLabel: "not_found"` برمی‌گردد.
- `send_sms` شمارهٔ گیرنده در `receptor`، خط مجاز در `lineNumber` و متن در `message` را می‌گیرد. رسید شامل `messageId` و `clientReferenceId` است. شناسهٔ پیام نشان می‌دهد درخواست ثبت شده است. برای تأیید تحویل، وضعیت پیام را جداگانه بگیرید.
- `send_bulk_sms` همان متن را با `message` و از `lineNumber` به شماره‌های یکتا در `receptors` می‌فرستد. سقف هر فراخوانی ۵۰۰ گیرنده است، مطابق سقف وب‌سرویس قاصدک. رسیدهایی که وب‌سرویس گزارش کرده در `data.recipients` هستند. گیرنده‌ای که رسید ندارد، نتیجهٔ تأییدشده ندارد.
- `send_otp` شماره را در `mobile`، نام قالب فعال را در `templateName` و مقادیر پارامترهای قالب را در `inputs` می‌گیرد. هر ورودی یک شیء با `param` و `value` است. رسید در `data.recipients` برمی‌گردد.

شماره را با ارقام انگلیسی در قالب `09xxxxxxxxx` وارد کنید و شناسه‌ها را به شکل رشته نگه دارید. متن ارسال تکی و گروهی حداکثر ۱۰۰۰ کاراکتر است. فیلدهایی مثل هزینه و زمان در صورت وجود در پاسخ وب‌سرویس برگردانده می‌شوند.

کدهای تحویل از وب‌سرویس قاصدک می‌آیند. [مرجع وضعیت پیامک و خطاهای قاصدک](https://ghasedak.me/docs)

- `0` بدون وضعیت، `1` لغوشده، `2` شماره در فهرست مسدود
- `3` تحویل به اپراتور، `4` نرسیده به گوشی، `5` رسیده به گوشی
- `6` خطای ارسال، `7` حالت خطایابی، `8` نامشخص

## پاسخ و خطا

نتیجهٔ اجرا هم در `structuredContent` و هم به‌صورت متن JSON برمی‌گردد. در خطا، سرور `isError: true` را هم در سطح MCP می‌گذارد. اگر نوع یا قالب ورودی با تعریف ابزار سازگار نباشد، SDK پیش از تماس با وب‌سرویس خطای اعتبارسنجی برمی‌گرداند.

نمونهٔ استعلام موفق اعتبار:

```json
{"ok":true,"data":{"credit":45210}}
```

نمونهٔ استعلام دو شناسه. پیام اول به اپراتور تحویل شده و شناسهٔ دوم پیدا نشده است.

```json
{"ok":true,"data":[
  {"messageId":"12345","status":3,"statusLabel":"accepted_by_carrier"},
  {"messageId":"12346","status":null,"statusLabel":"not_found"}
]}
```

نمونهٔ خطای ارسال:

```json
{
  "ok": false,
  "error": {
    "code": "insufficient_credit",
    "message": "Check the account credit before sending again.",
    "httpStatus": 200,
    "apiCode": 418
  }
}
```

- `config_error` یعنی کلید در تنظیمات محلی در دسترس نیست. `auth_error` یعنی کلید یا دسترسی حساب باید بررسی شود. `ip_restricted` به محدودیت IP مربوط است.
- `invalid_request` یا `request_too_large` یعنی ورودی، طول متن، تعداد گیرنده‌ها یا متن لغو باید بررسی شود. `invalid_message_link` و `invalid_message_characters` به محتوای متن مربوط‌اند.
- `line_unverified`، `precondition_failed`، `plan_required` یا `invalid_tariff` یعنی خط، شرایط حساب یا سرویس باید در پنل بررسی شود.
- `insufficient_credit` یعنی اعتبار کافی نیست. `invalid_template` و `template_parameter_not_found` یعنی نام قالب یا پارامترهای OTP باید بررسی شوند.
- `duplicate_request` یعنی قاصدک درخواست تکراری تشخیص داده است. ارسال قبلی را پیگیری کنید.
- `rate_limited` یعنی درخواست به محدودیت نرخ خورده است. `connection_error` و `service_unavailable` در استعلام یعنی اتصال یا دسترسی به سرویس مشکل دارد.
- `send_outcome_unknown` یعنی ممکن است درخواست ارسال ثبت شده باشد. با `error.clientReferenceId` استعلام بگیرید و درخواست را خودکار تکرار نکنید.
- `api_error` یعنی قاصدک درخواست را با کدی رد کرده که دسته‌بندی نشده است. `unexpected_response` و `internal_error` یعنی ابزار نتوانسته پاسخ معتبر تولید کند. اگر `apiCode` یا `httpStatus` وجود دارد، آن را برای بررسی نگه دارید.

کد HTTP و کد داخلی قاصدک جدا هستند. برای مثال کد داخلی ۴۲۹ به پارامتر قالب اشاره دارد. کد HTTP ۴۲۹ بدون کد داخلی شناخته‌شده به‌عنوان محدودیت نرخ گزارش می‌شود.

## نتیجهٔ نامشخص ارسال

ابزار برای هر درخواست ارسال یک شناسهٔ مرجع می‌سازد. اگر نتیجهٔ ارسال نامشخص بود، پیش از هر تصمیمی برای ارسال دوباره با همان شناسهٔ مرجع استعلام بگیرید. اگر گزارش هنوز پیدا نشده، بعداً دوباره استعلام بگیرید. ابزار ارسال را خودکار تکرار نمی‌کند.

## تست ارسال و تحویل

1. برای تست ارسال بگویید «با قاصدک از خط [خط مجاز] به شمارهٔ [شمارهٔ آزمایشی] پیام [متن تست] را بفرست. قبل از ارسال خط، شماره و متن را نشان بده و تأیید بگیر.» پس از تأیید، `data.messageId` را از رسید بردارید.
2. بپرسید «وضعیت تحویل پیام با شناسهٔ [شناسهٔ پیام] را بررسی کن.» فقط وضعیت `5` تحویل به گوشی را تأیید می‌کند.

نمونهٔ آرگومان‌های ارسال تکی. شماره‌ها را با مقادیر مجاز آزمایشی عوض کنید. اگر خط شما به عبارت لغو نیاز دارد، آن را مطابق تنظیمات خط در متن قرار دهید.

```json
{"receptor":"<TEST_MOBILE>","lineNumber":"<SENDER_LINE>","message":"پیام آزمایشی قاصدک"}
```

نمونهٔ آرگومان‌های ارسال OTP. نام قالب و پارامتر باید با مقادیر پنل یکی باشند.

```json
{"mobile":"<TEST_MOBILE>","templateName":"<TEST_TEMPLATE>","inputs":[{"param":"<PARAMETER_NAME>","value":"123456"}]}
```

## عیب‌یابی

- **سرور یا ابزارها دیده نمی‌شوند.** نسخهٔ Node و مسیر فرمان را بررسی کنید. برای اجرای سورس، در ریشهٔ مخزن `npm ci` بزنید. پس از تغییر تنظیمات، اتصال را دوباره راه‌اندازی کنید. اگر در Codex فقط بخشی از ابزارها دیده می‌شوند، فهرست `enabled_tools` را بررسی کنید.
- **اعتبار خوانده نمی‌شود.** برای `config_error` مسیر فایل کلید یا بخش `env` را بررسی کنید. برای `auth_error` اعتبار کلید و فعال بودن حساب را در پنل بررسی کنید.
- **ارسال رد می‌شود.** کد خطا را در بخش «پاسخ و خطا» بررسی کنید. برای خطای ورودی، شمارهٔ گیرنده، خط مجاز، متن و در صورت نیاز عبارت لغو را با تنظیمات پنل تطبیق دهید. برای OTP نام قالب و پارامترها را بررسی کنید.
- **رسید دارید و تحویل تأیید نشده است.** با `messageId` دوباره استعلام بگیرید. اگر خطای `send_outcome_unknown` دریافت کرده‌اید، شناسهٔ مرجع را در `ids` بگذارید و `idType` را روی `clientReferenceId` قرار دهید.

## ساختار پروژه

- `src/index.js` نقطهٔ اجرای سرور و اتصال `stdio`.
- `src/client.js` ارتباط با API قاصدک، خواندن پاسخ و تبدیل خطاهای سرویس.
- `src/errors.js` قالب مشترک نتیجه و خطا برای MCP.
- `src/tools/` یک فایل برای هر ابزار. برای افزودن ابزار، تعریف و اعتبارسنجی را در فایل خودش بگذارید و آن را در `src/tools/index.js` ثبت کنید.
